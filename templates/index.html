01

Airport network

Every airport is a node. Every connection is an undirected edge weighted by its great-circle distance, so the planner treats the network as a weighted graph.

02

Dijkstra shortest path

A min-heap priority queue expands the closest unvisited node first. Each relaxation keeps the cheapest known distance, guaranteeing the shortest path once the goal is finalised.

03

Haversine distance

Great-circle distance between two coordinates on a sphere. It feeds every edge weight, every leg distance and the total route distance shown in the dashboard.

04

Route optimization

Yen's algorithm spur-searches the pruned graph to surface loop-free alternatives, ranked by total distance, so the planner can compare the best path against realistic detours.

Haversine formula

The exact expression used in algorithms/distance.py.

a = sin²(Δφ/2) + cos φ₁ · cos φ₂ · sin²(Δλ/2)
c = 2 · atan2(√a, √(1−a))
d = R · c          R = 6,371.0088 km

For the distances involved in this network, the great-circle result is accurate well under one percent — close enough for comparative route planning.

Duration model

Planning estimates, never schedules.

  • 850 km/h cruise speed assumption.
  • 25 min taxi, climb and descent overhead per leg.
  • 60 min connection allowance per stopover.
  • No live timetables, availability or airline schedules.

Hackathon build

RouteX — a transparent flight path planning demo

RouteX turns a curated airport network into an interactive route planner. It computes the shortest path with Dijkstra, measures every hop with the Haversine formula, and visualises the result on a Leaflet map — with a clear line between real scheduled city-pairs and illustrative demo links.

What it does

  • Finds the shortest route between two airports.
  • Suggests loop-free alternatives ranked by distance.
  • Estimates duration from distance and stopovers.
  • Maps every result with fit-to-route bounds.

Technical stack

Python Flask Dijkstra Yen's k-shortest Haversine Leaflet OpenStreetMap Vanilla JS

The backend serves a single-page dashboard from Flask and exposes JSON endpoints for airports, routes and analytics. No external data services are called.

Data transparency

Airport coordinates are realistic reference values. A connection is labelled Real route when it corresponds to a scheduled city-pair that airlines have operated, and Illustrative when it exists only to make the demo graph interesting.

RouteX does not provide live schedules, real-time availability, pricing or booking, and it does not claim an airline affiliation.
